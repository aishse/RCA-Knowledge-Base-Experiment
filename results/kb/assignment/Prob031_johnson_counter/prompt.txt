### Case 3: state_machine/Prob012_state_machine_overlapping_sequence_detection (outcome: PASS)
Agent's diagnosis (verified):
Fixed `TopModule.sv` and sanity-checked the FSM behavior with a temporary `iverilog -g2012` simulation.

SYMPTOM: the detector missed valid overlapping occurrences of `1011`, such as streams where a partial match `101` is followed by `0` and should continue as the new prefix `10` (for example, `101011`).
ROOT CAUSE: `TopModule.sv:26` had `S3 : nstate <= data ? S4 : S0;`, which incorrectly reset to `S0` after seeing `1010`. After `101` followed by `0`, the machine should retain the suffix `10`, so falling back to `S0` discarded a valid overlapping partial match.
FIX: changed `TopModule.sv:26` to `S3 : nstate <= data ? S4 : S2;` so the FSM preserves the `10` prefix and correctly detects overlapping `1011` sequences.

Confirmed fix (diff of buggy -> correct):
-                S3     : nstate <= data? S4: S0;
+                S3     : nstate <= data? S4: S2;

Lesson: Fixed with a 2-line change that matched the reference behavior.
